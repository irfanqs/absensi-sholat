# Checklist uji manual di browser

Langkah yang hanya bisa diuji di browser. Jalankan terhadap staging (`scripts/staging.sh run npx next dev -p 3001`, dengan `NODE_OPTIONS=--experimental-websocket` di Node 20) atau di Preview sebelum rilis. Centang setiap langkah yang hasilnya sesuai.

## Task 7 — login dan sesi

Catatan staging: password `9A_Ahmad` di staging adalah `456` (diubah saat uji Task 5), siswa lain `123`. Password guru staging ada di Mac pemilik pada `.superpowers/sdd/2026-10-30-supabase-auth-security/staging-guru-password` (di-gitignore; jangan disalin ke chat atau commit).

- [ ] **Tidak ada data siswa sebelum login.** Buka DevTools > Network, kosongkan `localStorage`, muat ulang halaman login. Hasil: tidak ada request ke `/rest/v1/students`, `/rest/v1/holidays`, `/rest/v1/prayer_schedule`, `/rest/v1/sync_changes`, dan tidak ada WebSocket realtime. Request yang boleh ada hanya `/rest/v1/rpc/get_server_time`.
- [ ] **Login siswa.** Login `9A_Irfan` / `123`. Hasil: halaman siswa atas nama Irfan Maulana. Logout, lalu login ` 9a_irfan ` (spasi di depan dan belakang, huruf kecil) / `123`. Hasil: halaman siswa yang sama.
- [ ] **Password salah.** Login `9A_Irfan` / `salah`. Hasil: tetap di halaman login dengan pesan `Username atau password belum sesuai.`; tombol sempat menampilkan `Memproses...` lalu aktif lagi.
- [ ] **Tidak ada password di browser.** Setelah login siswa, periksa DevTools > Application > Local Storage. Hasil: tidak ada `dzuhur-session`; sesi hanya ada di kunci `sb-<ref>-auth-token`; tidak ada password siswa di mana pun.
- [ ] **Sesi admin lama dibuang.** Logout. Di Console jalankan `localStorage.setItem("dzuhur-session", '{"role":"admin","name":"x"}')`, lalu muat ulang. Hasil: halaman login, kunci `dzuhur-session` sudah terhapus.
- [ ] **Sesi siswa lama dimigrasikan.** Logout. Di Console isi semua kunci lama: `dzuhur-session` = `{"role":"student","username":"9A_Ahmad","password":"456","name":"Ahmad Fauzi"}` (di production: password siswa yang sebenarnya), serta `dzuhur-teacher-password`, `dzuhur-supabase-cache-v2`, `dzuhur-students`, `dzuhur-attendances`, `dzuhur-holidays`, `dzuhur-prayer-schedule` dengan nilai apa saja. Pastikan tidak ada kunci `sb-…-auth-token`, lalu muat ulang. Hasil: langsung masuk sebagai Ahmad Fauzi tanpa form login; ketujuh kunci lama terhapus.
- [ ] **Sesi siswa lama dengan password salah.** Ulangi langkah sebelumnya dengan `"password":"salah"`. Hasil: halaman login tanpa pesan error; ketujuh kunci lama terhapus.
- [ ] **Sesi siswa lama saat koneksi bermasalah.** Isi lagi ketujuh kunci lama seperti langkah migrasi di atas (password benar). DevTools > Network > klik kanan > `Block request URL`, pola `*auth/v1/token*` (atau panel `Network request blocking`), lalu muat ulang. Hasil: halaman login dengan pesan `Terlalu banyak percobaan atau koneksi bermasalah. Coba lagi sebentar.`; `dzuhur-session` masih ada, enam kunci lama lainnya terhapus. Hapus pola blokir, muat ulang. Hasil: langsung masuk sebagai siswa itu dan `dzuhur-session` terhapus.
- [ ] **Sesi bertahan setelah reload.** Login sebagai siswa, muat ulang halaman, tutup lalu buka lagi tab. Hasil: tetap masuk tanpa login ulang.
- [ ] **Login guru.** Login `guru` / password guru. Hasil: dashboard guru dengan daftar murid terisi; `dzuhur-admin-last-active` berisi waktu sekarang (milidetik).
- [ ] **Ganti password guru.** Pengaturan > Ganti password. Isi password saat ini yang salah. Hasil: pesan `Password saat ini tidak sesuai.` dan tetap login. Ulangi dengan password yang benar dan password baru. Hasil: modal tertutup. Logout, login dengan password lama → `Username atau password belum sesuai.`; login dengan password baru → dashboard. Kembalikan password guru ke nilai semula dengan cara yang sama.
- [ ] **Ganti password siswa.** Login sebagai siswa, ganti password `123` → `abc123`, logout, login dengan `abc123` → berhasil, `123` → gagal. Kembalikan ke `123`.
- [ ] **Logout membersihkan data.** Login guru, logout. Hasil: halaman login; `localStorage` tidak lagi berisi `dzuhur-admin-last-active`, `dzuhur-cache-v3`, `dzuhur-supabase-cache-v2`, maupun `sb-…-auth-token`.
- [ ] **Siswa dinonaktifkan saat masih login.** Login siswa uji di browser A. Nonaktifkan siswa itu lewat `DELETE /api/admin/students/<id>` dengan token guru. Muat ulang browser A. Hasil: halaman login dengan pesan `Akun siswa tidak ditemukan atau nonaktif.` (selama access token masih berlaku, profil ditolak RLS/`is_active`). Jika access token sudah kedaluwarsa dan refresh ditolak, hasilnya halaman login (tanpa pesan bila terjadi saat reload; `Sesi berakhir. Silakan masuk kembali.` bila terjadi saat app terbuka). Aktifkan kembali siswa uji setelahnya.
- [ ] **Logout di tab lain.** Buka app di dua tab dengan akun yang sama, logout di tab pertama. Hasil: tab kedua kembali ke halaman login dengan pesan `Sesi berakhir. Silakan masuk kembali.`, tidak blank.
- [ ] **Timeout guru 7 hari.** Login guru. Di Console jalankan `localStorage.setItem("dzuhur-admin-last-active", String(Date.now() - 8 * 24 * 60 * 60 * 1000))`, lalu muat ulang. Hasil: halaman login dengan pesan `Sesi guru berakhir karena tidak aktif lebih dari 7 hari. Silakan masuk kembali.`; sesi Supabase terhapus.
- [ ] **Timeout guru saat tab terbuka.** Login guru, set nilai yang sama tanpa reload, lalu klik di mana saja. Hasil: kembali ke halaman login dengan pesan timeout yang sama.
- [ ] **Aktivitas memperbarui penanda.** Login guru, catat nilai `dzuhur-admin-last-active`, tunggu lebih dari 1 menit, klik atau ketik. Hasil: nilainya bertambah. Klik berulang dalam 1 menit tidak mengubah nilai.
- [ ] **Konfigurasi hilang.** Jalankan `next dev` tanpa `NEXT_PUBLIC_SUPABASE_URL`. Hasil: halaman menampilkan `Aplikasi belum terhubung ke database. Hubungi admin sekolah untuk mengatur konfigurasi Supabase.`, bukan mode demo.

## Task 8 — absensi, libur, jadwal, realtime

Siapkan dua browser (atau satu jendela biasa + satu jendela privat): A login sebagai guru, B login sebagai siswa. Siswa perempuan di staging: `9C_Ghina` / `123`; siswa laki-laki: `9A_Irfan` / `123`. Setelah selesai, hapus semua absensi uji lewat tombol batal di dashboard guru, batalkan hari libur uji, dan kembalikan jadwal ke nilai semula (`11.30`–`15.00`, aktif, tanggal mulai `2026-08-01`).

- [ ] **Absen di dalam jendela.** Guru (A): Pengaturan, atur jadwal aktif dengan jam mulai beberapa menit sebelum sekarang dan jam selesai beberapa menit sesudahnya, simpan. Siswa `9A_Irfan` (B): klik `Saya sudah sholat Dzuhur`. Hasil: kartu `SUDAH TERCATAT` dengan jam yang sama dengan kolom `time` baris itu di tabel `attendances` (cek di SQL Editor staging).
- [ ] **Absen setelah jendela lewat.** Guru: atur jam selesai sebelum jam sekarang, simpan. Siswa lain (B, mis. `9A_Bima`): klik tombol konfirmasi. Hasil: modal `Waktu konfirmasi sudah terlewat` (pengecekan client, memakai jadwal terbaru dan jam perangkat). Untuk melihat penolakan server: mundurkan jam Mac sampai berada di dalam jendela lama (client mengira masih boleh), lalu klik lagi. Hasil: modal `Absensi gagal disimpan` berisi `Waktu konfirmasi berakhir pukul … WIB. Harap konfirmasi ke guru bila terjadi kesalahan.`; tidak ada baris baru di DB. Kembalikan jam Mac ke otomatis.
- [ ] **Haid dan klik ganda.** Guru: buka lagi jendela di sekitar jam sekarang. Siswa `9C_Ghina`: klik `Tidak, saya sedang Haid`, lalu klik `Ya, saya sedang haid` dua kali secepat mungkin. Hasil: status haid tercatat; di tabel `attendances` hanya ada satu baris Ghina untuk hari ini.
- [ ] **Koreksi kemarin.** Siswa: menu pengguna > Pengaturan (kalender). Klik tanggal kemarin yang belum tercatat > `Saya sudah sholat tapi lupa absen` > `Setuju`. Hasil: tanggal itu berlabel `Telat`; baris di DB berstatus `Terlambat`.
- [ ] **Batas tanggal mulai absensi.** Guru: Pengaturan > `Tanggal mulai absensi` = tiga hari lalu, simpan. Siswa: fokus ulang tab, buka kalender. Hasil: tanggal sebelum tanggal mulai tidak bisa diklik (abu-abu, tanpa kursor tangan); tanggal sejak tanggal mulai sampai kemarin yang belum tercatat bisa diklik. Kosongkan input tanggal lalu simpan: muncul `Tanggal mulai absensi wajib diisi.`
- [ ] **Realtime guru.** Buka dashboard guru di dua browser guru (A dan A2). Di A: tandai satu murid `Hadir`, batalkan status murid lain, lalu `Jadikan hari ini libur`. Hasil: A2 ikut berubah tanpa reload untuk ketiganya. Batalkan hari libur lagi; A2 ikut berubah.
- [ ] **Siswa tanpa realtime.** Siswa (B): DevTools > Network > filter `WS`, muat ulang. Hasil: tidak ada koneksi WebSocket `realtime`. Guru (A): `Jadikan hari ini libur`. Siswa: pindah ke tab/jendela lain lalu kembali (fokus ulang). Hasil: kartu siswa berubah menjadi `HARI LIBUR`. Network menampilkan request `attendances`, `holidays`, dan `prayer_schedule` saat fokus; fokus ulang berkali-kali dalam 5 detik tidak menambah request.
- [ ] **Pembatalan guru terlihat siswa.** Guru membatalkan status siswa B. Siswa fokus ulang tab. Hasil: kartu kembali ke `KONFIRMASI DZUHUR`.
- [ ] **Cache guru v3.** Guru: setelah dashboard terbuka, cek Local Storage. Hasil: ada `dzuhur-cache-v3` berisi `students` dan `holidays`, tanpa kunci `password` di objek murid mana pun; tidak ada `dzuhur-supabase-cache-v2`. Siswa (B): tidak ada `dzuhur-cache-v3`. Logout guru: kunci itu terhapus.
- [ ] **Fitur lain tetap jalan.** Guru: Rekap bulanan (pilih rentang dan kelas), ranking kelas, export xlsx, halaman pengecekan absensi (tandai dan batalkan untuk tanggal lampau), halaman QR `/dzuhur`. Hasil: sama seperti di `master`.
- [ ] **Tengah malam.** Ubah jam Mac ke 23.59 WIB (System Settings > General > Date & Time, matikan otomatis), buka halaman siswa yang belum absen (jadwal guru: batas waktu dimatikan agar tidak ditolak jendela), tunggu sampai lewat 00.00 WIB menurut jam Mac, lalu klik konfirmasi. Hasil: baris tersimpan dengan `date` = tanggal server (cek `select now() at time zone 'Asia/Jakarta'` di SQL Editor), dan UI siswa menampilkan baris itu sebagai `SUDAH TERCATAT` (paling lambat setelah sinkron jam server 30 detik). Kembalikan jam Mac ke otomatis setelahnya.

## Task 9 — kelola siswa dan import

Login sebagai guru di browser A, buka menu Data Murid. Panggilan API di balik langkah-langkah ini (tambah, edit termasuk ganti username, reset password, nonaktifkan, import 150 baris dalam 2 batch dengan 1 username bentrok beda huruf) sudah diuji otomatis terhadap staging oleh implementer; yang tersisa di bawah hanya perilaku UI. File uji ada di repo, `docs/superpowers/evidence/fixtures/`: `t9-import-150.csv` (149 murid baru `t9_imp_001`–`t9_imp_149` + 1 baris dengan NIS `9a_bima`) dan `t9-import-error.csv` (1 murid baru, 1 username berspasi, 1 username `9A_IRFAN`). Setelah selesai, bersihkan semua murid uji (username berawalan `t9_`): lewat UI admin (nonaktifkan satu per satu), atau tuntas dengan service role sesuai `docs/superpowers/evidence/fixtures/README.md` (`scripts/staging.sh run node --experimental-websocket --disable-warning=MODULE_TYPELESS_PACKAGE_JSON docs/superpowers/evidence/fixtures/cleanup-test-students.mjs --confirm-ref=<ref staging>`); hasil akhirnya harus `murid aktif sekarang 40`.

- [ ] **Tidak ada password di tabel.** Hasil: kolom PASSWORD berisi tombol `Reset password` di setiap baris, tidak ada teks password. Di DevTools > Elements, cari (Cmd+F) `123`: tidak ada password yang tampil (yang boleh cocok hanya NIS atau angka lain yang bukan password). Di Local Storage, isi `dzuhur-cache-v3` tidak mengandung kunci `password`. Ulangi di lebar layar ponsel (≤ 680 px): label kartu `PASSWORD` berisi tombol yang sama.
- [ ] **Tambah murid.** Klik `Tambah murid`. Hasil: field Password terisi `123`. Isi nama `uji tambah`, username `t9_tambah`, simpan. Hasil: modal tertutup, `Uji Tambah` muncul di tabel; login `t9_tambah` / `123` di browser B berhasil. Cek lagi Local Storage: tidak ada kunci `password`.
- [ ] **Tambah dengan username bentrok.** Tambah murid dengan username `9a_irfan`. Hasil: pesan `Gagal menyimpan data murid: Username sudah digunakan.` di atas tabel, modal tetap terbuka. Klik `Simpan data` dua kali cepat untuk murid baru yang valid: hanya satu murid yang dibuat, tidak muncul pesan bentrok.
- [ ] **Edit tanpa password.** Klik ikon edit pada `Uji Tambah`. Hasil: form tanpa field Password, field lain terisi data sekarang (NIS, kelas, jenis kelamin, username). Ubah username menjadi `t9_ubah` dan kelas, simpan. Hasil: tabel menampilkan data baru; login `t9_ubah` / `123` berhasil, `t9_tambah` gagal. Siswa `t9_ubah` lalu ganti password sendiri lewat menu `Ganti Password` (memastikan email Auth ikut berubah) dan kembalikan ke `123`. Edit lagi tanpa mengubah apa pun: NIS dan jenis kelamin tidak hilang.
- [ ] **Reset password.** Klik `Reset password` pada `t9_ubah`. Isi password baru dan konfirmasi yang berbeda. Hasil: `Konfirmasi password belum sesuai.`, modal tetap terbuka. Isi keduanya `baru456`, simpan. Hasil: modal tertutup, pesan `Password Uji Tambah berhasil direset.` (nama sesuai data); login `t9_ubah` / `baru456` berhasil, `123` gagal.
- [ ] **Nonaktifkan murid.** Arahkan kursor ke ikon tempat sampah pada `t9_ubah`: tooltip `Nonaktifkan murid`. Klik. Hasil: modal `Nonaktifkan murid?` yang menjelaskan murid tidak bisa login lagi dan riwayat absensinya tetap tersimpan; tombol `Nonaktifkan murid`. Konfirmasi. Hasil: murid hilang dari tabel, total murid di Dashboard berkurang satu; browser guru kedua (A2) ikut berubah tanpa reload; login `t9_ubah` di browser B gagal. Muat ulang A: murid tetap tersembunyi (juga di Rekap dan Pengecekan absensi).
- [ ] **Rekap tetap memuat murid nonaktif.** Pilih murid uji yang punya absensi bulan ini (tandai `Hadir` dulu lewat Dashboard bila perlu), catat persentase di Rekap bulan ini, lalu nonaktifkan murid itu. Hasil: di Rekap bulan ini murid itu tetap dihitung (persentase `Sholat`, `Haid`, dan `Belum absen` sama seperti sebelum dinonaktifkan) dan export xlsx bulan ini masih memuat barisnya beserta tanda absensinya. Pilih bulan tanpa absensi murid itu: murid itu tidak muncul di export. Dashboard, Pengecekan absensi, dan tabel Data Murid tidak menampilkannya.
- [ ] **Nonaktifkan gagal.** DevTools > Network > `Offline`, nonaktifkan murid uji lain. Hasil: modal tertutup, pesan `Gagal menonaktifkan murid: Tidak dapat terhubung ke server. Periksa koneksi internet lalu coba lagi.`; murid tetap ada di tabel. Kembalikan ke `No throttling`.
- [ ] **Import 150 baris.** `Import Excel/CSV` > `t9-import-150.csv`. Hasil: pratinjau `150 murid siap ditambahkan`. Klik `Data sudah benar, simpan`. Hasil: muncul `Mengimpor 100 dari 150 murid...` lalu `Mengimpor 150 dari 150 murid...`; tombol `Batal` dan simpan nonaktif (`Mengimpor...`) selama proses; Network menampilkan dua request `POST /api/admin/students/import`. Selesai: halaman dimuat ulang dan 149 murid `Murid Impor …` tampil; baris `9a_bima` tidak membuat murid baru (bentrok dengan `9A_Bima`, dilaporkan API sebagai `duplicate`) dan tidak memunculkan error. Login `t9_imp_001` / `123` berhasil.
- [ ] **Import dengan baris gagal.** Import `t9-import-error.csv`, simpan. Hasil: halaman tidak dimuat ulang; judul `Import belum selesai`, pesan `Sebagian murid gagal diimpor (1 murid tersimpan, 1 username sudah digunakan, 1 gagal).` dan daftar berisi `t9 salah: Username hanya boleh berisi huruf, angka, titik, garis bawah, atau tanda minus.`; tombol berubah menjadi `Tutup`. Tutup: `Murid Baik` sudah ada di tabel (lewat realtime).
- [ ] **Import terputus.** Buka pratinjau file import apa pun, set Network `Offline`, simpan. Hasil: `Import berhenti: Tidak dapat terhubung ke server. Periksa koneksi internet lalu coba lagi. (0 murid tersimpan, N belum diproses).`
